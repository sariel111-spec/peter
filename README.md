# AFTER CLASS · 彼得的私人宇宙

以《超凡蜘蛛侠》彼得·帕克为梦角的私人同人档案网站。独立项目，不修改「一枕清欢」。内置 AI 已按用户要求取消。

## 页面与交互

- 独立线索墙首页 `/`：按用户提供的三篇小红书参考帖重做，以木框、软木板、红线、图钉、夹子与 23 份线索素材呈现。直接提取原帖科研文件、手写配方、蜘蛛显微图与加菲杂志剪报，排除格温及其他版本蜘蛛侠的区域。点击任意照片经蛛丝转场进入 `/archive` 档案站；保留整墙放大探索与光线切换，手机端采用独立竖版排布。首屏在服务器读取已保存墙面，等待实际图片和手机布局就绪再显示，避免先展示默认墙；浏览器返回首页时重新读取保存版。
- 首页 DIY 编辑器：批量导入原比例照片、替换 / 删除、自由移动 / 缩放 / 旋转、图钉 / 夹子 / 胶带与连线固定点、红线连接、便签、多选对齐、复制、隐藏、锁定、撤销 / 重做；图层列表支持手柄上下拖放、边缘自动滚动和键盘 ↑↓ 排序，列表顶端对应墙面最前层。
- 桌面 / 手机独立布局，底板与边框可调；自动保存、手动保存、账号隔离的本机草稿与版本冲突处理。支持整墙 PNG 导出、含原图的线索墙 JSON 备份与恢复。
- 档案站总览以影像卡片导航六个栏目，首页无档案侧栏。站内左侧导航，手机端抽屉导航。320px 起适配，支持键盘和减少动态效果偏好。
- 故事线：可拨动弧形时间刻度 + 树形目录。自定义大点 / 小点、自由时间标签、逐层细分（最多 64 层）、配图拖动阅览 / 全文阅读；手柄拖动整段排序 / 归入子层、上级选择器、撤销 / 重做、展开 / 收起。旧故事作为顶层时间点保留；移除上级点后子点上移，恢复后回到原层级。
- 灵感剪贴簿：图片卡片、标签导航、全文阅读、编辑 / 回收。随机牌堆仅抽取当前未删除的灵感，新增、编辑、回收、恢复实时更新，存在多枚时避免连续重复；抽到后打开原记录继续写。切换回页面或其他标签页保存时同步牌堆。
- 画稿收藏馆：按组批量上传，原比例大图 / 缩略图、图组放大翻阅、标签检索、进度、创作笔记和附件排序。
- 文字稿件栏目已移除；旧文字稿件只保留在完整备份中，不再出现在栏目、新建菜单或档案总览。
- 传讯：可拖动排序的时间点导航、按时间与标签成册；批量上传聊天截图，横向翻看 / 原图放大、调整图片顺序、备注及自定义时间刻度。
- 问题：待问 / 已问、补充说明和答案记录。
- 网站集：URL、分类、标签、笔记及外链入口。预置 Character.AI 和 SillyTavern 官方入口，可替换为用户实际使用的网站。
- 影像收藏室与角色 / 自设档案。
- 分类内搜索（含正文、标签、附件名称）、状态筛选、收藏筛选、网格 / 列表。
- 回收站、恢复、永久删除；完整 JSON 导出 / 导入，备份包含附件原始字节。

初始示例带有「示例」标签；大学 AU 与正文为可编辑同人示例，不视为电影官方剧情。

## 数据与访问

Sites 托管登录与私人访问控制。API 以平台签发的用户 ID 隔离数据；未登录返回 401。D1 保存记录、线索墙与时间目录，R2 保存附件。编辑使用 revision 冲突检查，避免覆盖其他页面刚保存的内容。记录初始化幂等。

单文件上限 20MB，支持常用图片、PDF、DOCX、TXT 与 Markdown。SVG / HTML 不作为附件接受。附件请求再次校验所有者；下载使用 no-store 与 nosniff。备份为用户本地 JSON 文件；档案导入作为新记录添加，重复导入会产生副本。v3 完整备份包含分层时间目录、传讯顺序、线索墙及原图，仍兼容 v1 / v2；导入新记录时重映射时间点 ID，保留分层关系。v2 起包含线索墙及原图，导入时单独确认是否替换线索墙；线索墙专用备份仅替换墙面，可撤销。仍被线索墙引用的图片不会随档案记录删除。

## 本地开发

Node 22.13+。使用 Sites 脚本进行依赖安装与构建。

```sh
npm run dev -- --host 127.0.0.1 --port 4173
```

首次预览使用页面登录入口完成框架提供的本地模拟登录；生产登录由 Sites 提供。执行数据库迁移方式见 Sites 的 Vinext 模板说明。已生成的迁移在 `drizzle/`。

```sh
node node_modules/typescript/bin/tsc --noEmit
npm run build
npm run test:api
npm run test:wall
npm run test:wall-api
npm run test:chronology
npm run test:chronology-api
npm run test:inspiration
npm run test:portal-api
```

`test:api` 只允许 localhost / 127.0.0.1 的预览地址，验证登录隔离、七类记录、文件上传 / 下载、格式校验、编辑冲突、收藏、回收 / 恢复与删除附件。它会清理自己创建的测试记录，不用于生产。`test:wall` 验证旋转锚点、自由缩放、图结构和图层重排；`test:wall-api` 验证线索墙隔离、保存冲突、非法文档拒绝、上传文件归属和跨档案附件保留，结束时恢复测试前墙面。

## 统一阅读器

故事、灵感、传讯记录、传讯问题不再提供或展示封面；旧封面字段仅为数据兼容保留，不删除原附件。配图依照附件顺序进入统一阅读器，长图可上下滚动 / 抓手拖动，放大后支持横向平移，提供适宽、整图、阅读进度、回顶与原图下载；多图用明确的前后按钮和目录选择。拖图不触发换图。触屏保留原生滑动和双指缩放。

全文阅读直接展示标题、正文和附件，固定工具栏含图片目录与正文抓手开关。默认可选中文字，抓手模式可拖动正文；图片始终可抓手阅读。四类编辑器取消封面选择，但画稿首图和人物档案照片仍可选。所有附件图片在编辑器内也能展开阅读。

`node --test tests/media-model.test.mjs` 验证封面隔离、附件保留 / 顺序 / 去重，以及缩放中心。详见 `design/reader-audit.md` 的本轮浏览器检查记录。

## 紧凑传讯与入站加载

传讯默认双列相册，宽屏三列；列表视图使用文字与图片并排的小相册，手机为单列。缩略阅读区保持约 150–210px 高，仍按原图比例拖动阅读，展开阅读不受缩略高度限制。标题也可打开全文。传讯页标题、标签与时间排序栏的间距同步缩小。

首页墙面减少外侧留白并适配可用屏幕高度，不改写已保存的照片尺寸、位置、图层、装饰与红线。原有桌面 / 手机独立排版继续使用。

入站改为客户端路由，持久蛛丝幕布在新页面及主图准备好后揭开。首页在墙面显示后预加载档案代码、总览主图、记录与时间目录；记录仅在内存中短暂缓存 8 秒并消费一次，不写入浏览器存储。旧的“播放后整页跳转、再次显示入场动画”流程已移除。连接超时提供重试 / 返回入口，减少动态效果偏好下跳过位移动画。

`node --test tests/archive-preload.test.mjs` 覆盖一次性消费、过期更新与失败认证响应不被缓存。

## 人物关系图（故事时间线 → 人物关系图）

- 添加人物：点「添加人物」或双击画布空白处；拖动卡片摆位置。
- 连线：拖动卡片右下角的红色蛛丝按钮到另一个人物上，再写下关系。
- 编辑：单击人物或关系，右侧信息栏可改名字、身份、头像、颜色、详情、线型与箭头；双击（或「展开详细编辑」）打开大编辑窗。
- 删除：信息栏「删除」需要再点一次确认；支持撤销 / 重做（Ctrl/⌘+Z）。
- 数据保存在时间目录（`chronologies.doc.cast`）里，随完整备份一起导出和导入，不需要新的数据库迁移。

## 设定速览（我们的设定 页面顶部）

- 一张对开的双人档案：两侧是各自的照片、名字、基本资料、自定义项目和「锚点」，中间是合照、纪念日天数、关系进程、彼此的称呼与印象、结局倾向、主题曲和 TAG。
- 所有文字直接点击就能改，停止输入后自动保存；带「增删 / 编辑」字样的地方可以增删条目。
- 下方是「关系定位」（勾选，可增删选项）和「谁更……」（拖动爱心偏向某一方，问题可增删改），以及世界观。
- 右上角可以在「展示」和「编辑」之间切换：展示时隐藏所有空项和表单痕迹，内容不会被误改；编辑时每一处都能直接改。已经填过内容时默认打开展示。
- 照片会跟着鼠标轻微倾斜并带一道反光；「在一起的第 N 天」和身高差的数字出现时会滚动到位。
- 身高差：两人的身高写成 178cm 或 1.63m 这样的数字，就会按比例画出站在一起的样子和相差的厘米数。
- 问答卡：可以「抽一题」从常见问题里随机取一个，也可以自己写；展示时点卡片翻面看回答，编辑时可改、可删、可调顺序。
- 「存为设定卡图片」会把当前内容排成一张长图下载，方便保存或分享。
- 数据保存在时间目录（`chronologies.doc.duo`）里，随完整备份导出导入；原有的设定卡片照常保留在下方。

## 档案总览

- 封面标题和副标题可以点击修改（标题换行后第二行显示为红色）；右上角印章显示两人名字和在一起的天数。
- 「我们走到了」读取设定里的关系进程；「今日一句」从你自己写的语录里每天取一句；「纪念日」按 2012-08-10 这样的日期自动倒数。
- 八个房间卡片显示各自的数量和最近一条；下方是最近留下的片段和还没问出口的问题。

## 内容安全：更新代码不会丢内容

- 你的内容（档案、附件、时间目录、人物关系图、设定、线索墙）存在云端数据库和文件存储里，和网站代码是分开的。重新发布代码只替换页面程序，不会动数据。
- 新功能的数据都以「可选字段」的方式加进原有记录，没有改动或删除任何旧表、旧字段，所以新旧版本读到的旧内容是一样的。
- 即使有一个页面还开着旧版本，它保存时间目录时也不会抹掉人物关系图和设定速览（服务器会保留它不认识的部分）。
- 删除档案先进回收站；人物关系图支持撤销。

## 备份与导入

- 导出：设置 → 导出完整备份。一个 JSON 文件，包含所有档案（含回收站）、原附件、时间目录、人物关系图、设定速览、语录与纪念日、线索墙。设置里会显示这台设备上次备份的时间，超过 14 天总览页会提醒。
- 导入：先列出这份备份里有什么、哪些是新的，确认后才开始。和现有内容完全相同的档案自动跳过，同名同身份的人物会合并，线索墙和现在一样时跳过；不会覆盖或删除现有内容，所以同一份备份导入多次也不会重复。

## GitHub Pages 版本（内容存进你的私有仓库）

同一套页面也可以作为静态网站放在 GitHub Pages 上。Pages 没有服务器，所以原来由服务器负责的读写，改由浏览器里的 `ghpages/sw.js` 接管：内容先存在这台设备的浏览器里，再自动同步到你指定的 **私有** GitHub 仓库（`data/state.json` 放档案、时间目录、人物关系图、设定和线索墙，`assets/` 放原附件）。

- 构建：`npm run build:pages`，产物在 `docs/`（源码在 `ghpages/`，不能叫 `pages/`，否则会被当成站点路由）；仓库 Settings → Pages 选择 `main` 分支的 `/docs`。
- 第一次打开会让你填 GitHub 用户名、私有仓库名和一个只对该仓库有 Contents 读写权限的 fine-grained 令牌。令牌只保存在当前设备的浏览器里，不会进入代码或仓库。
- 右下角的小云朵显示同步状态，可以手动同步，或在这台设备上断开。
- 多台设备同时修改时，按每条档案较新的版本合并；时间目录和线索墙以较新的整份为准。
- 从 chatgpt.site 版本搬家：在那边导出完整备份，在这边的设置里导入即可。
- 任何人都能打开 Pages 的网址，但没有令牌就读不到你的内容；素材图是公开的。
